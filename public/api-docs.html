PMHelper API

REST API for the PMHelper mobile app. Exposes the six core modules — projects, tickets, daily reports, weekly reports, discussions, and users — so native iOS and Android clients can consume the same data the web dashboard uses.

The API is additive: the Filament admin web dashboard keeps its existing Livewire-based flows. All endpoints live under /api, share Eloquent models + policies with the web side, and reuse the same Pusher private channels for realtime ticket updates.

Base URL

All endpoints are relative to:

https://pm.digicrats.com/api

Authentication

The API uses Laravel Sanctum with plain-text bearer tokens. Obtain a token by calling POST /auth/login, then include it as a Authorization header on every subsequent request:

Authorization: Bearer 1|abc…xyz
Accept: application/json

Tokens are user-scoped and revocable. Call POST /auth/logout to invalidate the current token on logout.

Response Format

All successful responses return JSON. Single resources and collections are nested under a data key; paginated collections add a meta block.

Single resource:

{
  "data": { "id": 1, "name": "Example" }
}

Paginated collection:

{
  "data": [ ... ],
  "meta": {
    "current_page": 1,
    "last_page": 5,
    "per_page": 25,
    "total": 123
  }
}

Errors

The API uses standard HTTP status codes. Error responses include a message field; validation errors also include a structured errors map.

CodeMeaning
200OK — request succeeded
201Created — resource successfully created
401Unauthenticated — missing or invalid token
403Forbidden — authenticated but lacks permission
404Not Found — resource doesn't exist
422Unprocessable — validation failure
500Server Error — unexpected failure

Validation error shape:

{
  "message": "The week start has already been taken.",
  "errors": {
    "week_start": ["The week start has already been taken."]
  }
}

Realtime Events

Ticket moves broadcast via Pusher Channels on a private channel per project. Mobile clients should subscribe with Pusher's native iOS/Android SDK or pusher-js and listen for ticket.moved events.

Channel
private:project.{id}.kanban
Event
ticket.moved

Event payload:

{
  "project_id": 1,
  "ticket_id": 42,
  "old_status_id": 3,
  "new_status_id": 5,
  "new_index": 0,
  "moved_by_user_id": 7
}
Tip: Skip events where moved_by_user_id equals the current user — those are your own optimistic updates.

Auth

POST /auth/login

Login

Exchange email + password for a bearer token. No auth required.

Request Body

FieldTypeDescription
emailstring, requiredUser email
passwordstring, requiredUser password
device_namestring, optionalLabel shown in DB (falls back to User-Agent)

Example Request

curl -X POST https://pm.digicrats.com/api/auth/login \
  -H "Content-Type: application/json" \
  -H "Accept: application/json" \
  -d '{
    "email": "user@example.com",
    "password": "secret",
    "device_name": "iPhone 15"
  }'

Example Response 200 OK

{
  "token": "1|abc...xyz",
  "user": {
    "id": 2,
    "name": "Bintang Jerry",
    "username": "bintangjerry",
    "email": "user@example.com",
    "avatar_url": "/storage/avatars/2_1775191617.jpg",
    "status": null,
    "status_message": null
  }
}
POST /auth/logout

Logout

Revokes the current access token. Requires authentication.

Example Response 200 OK

{ "message": "Logged out" }

Projects

    {
      "id": 1,
      "name": "PMHelper",
      "description": "Internal project management tool",
      "ticket_prefix": "PMH",
      "type": "kanban",
      "status_type": "default",
      "owner": { "id": 1, "name": "Admin", "email": "..." },
      "status": { "id": 1, "name": "Active", "color": "#10b981" },
      "tickets_count": 42,
      "members_count": 5,
      "created_at": "2026-01-01T00:00:00+07:00",
      "updated_at": "2026-04-17T09:00:00+07:00"
    }
  ]

GET /projects/{id}

Get Project

Returns a single project by ID. User must own or be a member of the project (403 otherwise).

Example Response 200 OK

{
  "data": {
    "id": 1,
    "name": "PMHelper",
    "description": "…",
    "ticket_prefix": "PMH",
    "type": "kanban",
    "owner": { "id": 1, "name": "Admin" },
    "tickets_count": 42,
    "members_count": 5
  }
}
GET /projects/{id}/tickets

Project Tickets

Paginated list of tickets in a project, with owner/responsible/status/type/priority eager-loaded.

Query Parameters

ParamDescription
status_idFilter by status ID
mine1 to show only tickets owned by or assigned to you
sort_byupdated_at (default) · created_at · priority · due_date · order
per_pageItems per page (default 25)

POST /tickets

Create Ticket

Requires Create ticket permission and project access.

Request Body

FieldType
namestring, required, max 255
contentstring, required
project_idinteger, required
responsible_idinteger, optional
type_idinteger, optional (defaults to is_default type)
priority_idinteger, optional (defaults to is_default priority)
status_idinteger, optional (defaults to is_default status)
epic_idinteger, optional
sprint_idinteger, optional
estimationnumeric, optional (hours)
due_datedate, optional

Example Request

{
  "name": "Add dark mode toggle",
  "content": "Settings page should have a toggle to switch themes.",
  "project_id": 1,
  "priority_id": 3,
  "estimation": 4,
  "due_date": "2026-04-25"
}
PATCH /tickets/{id}

Update Ticket

Partial update. Requires ticket update permission. Accepts any subset of the fields listed in Create Ticket.

DELETE /tickets/{id}

Delete Ticket

Soft-deletes the ticket. Requires delete policy on the ticket.

POST /tickets/{id}/move

Move Ticket

Change the ticket's status and order. Broadcasts ticket.moved on the project kanban channel so web + mobile clients stay in sync.

Request Body

{
  "status_id": 5,
  "order": 0
}
Permission: The target status's canBeSetByUser check runs — returns 403 if the user's role is not allowed to set that status.

Ticket Comments

GET /tickets/{id}/comments

List Comments

Returns all comments on the ticket, ordered by creation time.

POST /tickets/{id}/comments

Add Comment

Adds a comment to the ticket. Triggers mention notifications via existing boot logic.

Request Body

{ "content": "LGTM — shipping tomorrow!" }
DELETE /ticket-comments/{id}

Delete Comment

Only the comment author or anyone with update permission on the parent ticket may delete.

Lookups

Helper endpoints that return the lists used in dropdowns when creating or filtering tickets.

GET /ticket-statuses

Ticket Statuses

Pass ?project_id=X to include project-custom statuses alongside the global ones.

Example Response

{
  "data": [
    { "id": 1, "name": "Backlog", "color": "#6b7280", "order": 0, "is_default": true },
    { "id": 2, "name": "In Progress", "color": "#3b82f6", "order": 1, "is_default": false }
  ]
}
GET /ticket-types

Ticket Types

Returns all ticket types (Task, Bug, Feature, Request, etc.) with their color and icon.

GET /ticket-priorities

Ticket Priorities

Returns priorities in alphabetical order (Blocker, Critical, High, Low, Normal).

Daily Reports

Daily standup-style reports. Unique per (user, date, project) — attempting to create a duplicate returns 422.

GET /daily-reports

List Daily Reports

Returns a paginated list. Defaults to the current user's own reports.

Query Parameters

mine0 to include team reports you have access to (default 1)
project_idFilter by project
from / toDate range filter (YYYY-MM-DD)
per_pageItems per page (default 25)
GET /daily-reports/{id}

Get Daily Report

Returns a single report if the user is the owner or has project access.

POST /daily-reports

Create Daily Report

Request Body

FieldType
project_idinteger, required
report_datedate, required, unique per user+project
accomplishedstring, optional
plansstring, optional
blockersstring, optional
statusdraft or submitted (default: draft)

Setting status to submitted stamps submitted_at = now().

PATCH /daily-reports/{id}

Update Daily Report

Only the report owner can update. Transitioning status from draft → submitted stamps submitted_at.

DELETE /daily-reports/{id}

Delete Daily Report

Owner-only.

Weekly Reports

Weekly summaries. Unique per (user, week_start).

GET /weekly-reports

List Weekly Reports

Paginated. Accepts mine, project_id, per_page query params.

GET /weekly-reports/{id}

Get Weekly Report

Accessible to owner or anyone with project access.

POST /weekly-reports

Create Weekly Report

Request Body

FieldType
project_idinteger, required
week_startdate, required, unique per user
week_enddate, required, ≥ week_start
contentstring, optional
statusdraft or submitted
PATCH /weekly-reports/{id}

Update Weekly Report

Owner-only. Supports content and status partial update.

DELETE /weekly-reports/{id}

Delete Weekly Report

Owner-only.

Discussions

Threaded discussions scoped to a project, optionally tied to a ticket.

GET /discussions

List Discussions

Paginated list across all projects the user has access to. Filter by project_id or status.

GET /discussions/{id}

Get Discussion

Returns the discussion with all replies eager-loaded (chronological).

POST /discussions

Create Discussion

Request Body

{
  "project_id": 1,
  "ticket_id": 180,          // optional — link to a ticket
  "title": "Should we migrate to v2?",
  "content": "…markdown…",
  "priority": "normal",      // optional
  "status": "open"           // optional, defaults to open
}
PATCH /discussions/{id}

Update Discussion

Creator or project owner only. Changing status to resolved stamps resolved_by + resolved_at automatically.

DELETE /discussions/{id}

Delete Discussion

Creator or project owner only.

POST /discussions/{id}/replies

Add Reply

Any project member can reply.

Request Body

{ "content": "Agreed — let's schedule a call." }
DELETE /discussion-replies/{id}

Delete Reply

Reply author only.

Users

List Users

GET /users/{id}

Get User

Returns a single user with department + position.
